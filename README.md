# 手表离开锁屏 / WatchSignal

个人使用的 macOS 原生工具：跟踪你选定的 Apple Watch 蓝牙 RSSI，完成两步校准后，在判定离开工位时立即请求系统锁屏。**Apple Watch 不需要安装应用。**

当前版本：0.2.1。前一个诊断版的校准、信号图表和 CSV 导出继续保留。

## 构建和运行

macOS 14+，Swift 6 工具链及 Command Line Tools；无第三方依赖。本机用 Swift 6.4、macOS 27.0.1 验证。

```sh
swift run --build-system native DiagnosticsTests
bash scripts/build-app.sh
open dist/WatchSignal.app
```

`dist/WatchSignal.app` 可双击运行。本地 ad-hoc 签名用于个人使用，没有 Developer ID 公证或 App Store 发布；重新构建后系统可能要求重新授权。Swift 6.4 对 `--build-system native` 有弃用警告，本机仍可用。

## 第一次使用

1. 点击“开始扫描”，允许蓝牙访问。
2. 将自己的手表靠近、移远，观察候选设备信号是否同步变化。在左侧选中设备，点击“确认这是我的手表”。不要只凭名称选择。
3. 完成下面的两步校准。若之前已保存有效校准，可以继续使用或重新采集。
4. 点击“授权锁屏权限”，在“系统设置 → 隐私与安全性 → 辅助功能”允许 **手表离开锁屏 / WatchSignal**。必要时添加当前 `WatchSignal.app`，或重新授权、重启应用。
5. 点击“立即锁屏（测试）”，确认 Mac 真的进入锁屏，再解锁回来。
6. 打开“自动锁屏”，回到工位，等界面显示“在工位附近”和“检测已生效”。然后测试离开、返回。

如果系统设置中的权限已开启，但应用仍显示“需要辅助功能权限”，请完全退出 WatchSignal 后重新打开；本机实测授权后的原进程需要重启才识别到权限。重启后还需开始扫描和开启自动锁屏。

每次重启应用都需手动开始扫描和打开自动锁屏。应用不读取登录密码、不注册开机启动、不执行自动解锁。

## 两步校准

- 点击“1 采集工位信号”，保持常用坐姿，采集 20 秒。
- 完成后点击“2 采集离开信号”，带着手表走到希望锁屏的位置，尽快站定，等满 20 秒。
- 每组至少需 10 个有效样本，工位与离开中位数相差至少 10 dB；不足时明确报错，不生成有效校准。
- 离开阈值为近远中位数的中点；返回阈值比离开阈值高 6 dB。校准结果保存，可随环境变化重新采集。
- 校准期间暂停离开锁屏判断。完成后需回到工位建立新的在场起点；这时界面明确提示“尚未生效”，不会将离开位置的校准样本直接当成一次自动锁屏。
- 更换目标设备时清除原设备校准并关闭自动锁屏。

## 何时锁屏

仅处理所选 UUID 的有效 RSSI，用 EMA 平滑（新样本权重 0.25）。先收到至少 5 个有效目标样本且平滑信号达到返回阈值，建立在场起点。

- 平滑信号连续低于离开阈值 **8 秒**，判定离开，并在同一次回调/计时器处理中直接请求锁屏。
- 最后目标样本超过 5 秒显示过期；已建立在场起点后，**20 秒**无信号判定失联并请求锁屏。
- 8 秒、20 秒是判定本身的防抖条件，判定成立之后没有额外锁屏倒计时。计时器每秒检查一次。
- 同一次离开只请求一次；信号达到返回阈值持续 3 秒后确认返回，下一次离开可再次请求。20 秒以上的采样中断后恢复时需要重新建立在场起点。
- 暂停扫描、蓝牙不可用、系统睡眠期间不请求自动锁屏。恢复/唤醒后重新建立在场起点。
- 关闭自动锁屏仍可采集、分析信号；重新打开会丢弃旧判定，不补执行历史锁屏事件。
- 权限被撤销或发送请求失败时关闭自动锁屏并显示错误，避免静默失效或反复请求。

系统执行层使用公开的 Core Graphics 事件接口发送 **Control–Command–Q**，需辅助功能权限。`CGEvent.post` 不提供“已锁屏”的回执，因此记录显示 **已发送锁屏请求**，不把它当作锁屏结果的确认；实际生效用测试按钮和戴表走开验证。Mac 的默认锁屏快捷键如被改动，需恢复默认或调整实现。

锁屏快捷键发送后等待约 0.75 秒，再用 `/usr/bin/pmset displaysleepnow` 请求显示器休眠；该间隔用于顺序安排，不是系统已锁屏的回执。应用不执行 `sleepnow`，也不更改电源管理设置。Mac 后续是否自行进入系统睡眠仍由原有系统设置决定。手动测试按钮使用相同的锁屏、熄屏流程。

回来后按键或触控板唤醒显示器，由 macOS 自己尝试 Apple Watch 自动解锁。应用不模拟登录、不输入密码，也不强制调用手表解锁。熄屏后唤醒能否改善自动解锁，需要用户实机验证；不能仅凭命令成功退出认定手表解锁成功。

## 设备识别和数据

绑定由用户确认的 UUID；其他手表不会替代目标。UUID 是 macOS 为蓝牙设备分配的标识，不是序列号或所有权证明。重置、重新配对或地址变化后可能需重新选择。RSSI 能判断信号变化，不能精确换算距离；手表熄屏后是否持续广播需实机验证，信号丢失也不一定表示人离开。

设备名称、UUID 和校准保存在 `~/Library/Application Support/WatchSignal/selection.json`。CSV 仅主动导出到本地，不上传。

图表保留最近 120 秒；离开判定和锁屏请求列表各最多 500 项，界面显示最近 8 个请求。CSV 记录本次会话最近 50,000 行，截断会显示计数。

- 顶部是当前校准摘要；逐行保留当时的校准版本、阈值和样本数。
- `departure` 行表示检测器判定离开，自动锁屏关闭时也可能出现。
- `lockRequest` 行表示一次锁屏执行尝试；`event_reason` 为 `weakSignal`、`missingSignal` 或手动测试 `manual`。
- `lock_result=requested` 表示快捷键已发送；`failed` 表示请求失败，原因写入 `detail`。它们均不是系统实际锁屏的确认回执。
- `displaySleepRequest` 单独记录显示器休眠命令结果；`requested` 表示命令已成功退出，`failed` 表示执行失败，不与锁屏请求混为一项。
- 日志未逐次记录每次定时器状态或扫描暂停、恢复；分析信号空档时需结合实际操作时间。

## 验证范围

自动测试通过独立 Swift 可执行程序运行（本机 CLT 没有 XCTest）：`Core`、`Platform`、`Lock` 可筛选，未提供参数运行全部；断言失败或筛选不到测试返回非零退出码。

测试验证近远校准、单目标隔离、EMA、防抖/失联边界、暂停/睡眠恢复、参数保存/CSV，以及离开判定同次调用执行锁屏、一次离开仅执行一次、返回后重触发、权限拒绝/撤销和错误记录。测试替换 OS 锁屏副作用，不会锁住测试机器。

戴表实机验收：先确认“立即锁屏”按钮有效，再开启自动锁屏并等“检测已生效”，离开 30 秒、返回 10 秒，重复 5 次并记录时刻。还需检查坐在桌前和手表熄屏时是否误锁；自动测试不证明蓝牙广播稳定或系统锁屏实际成功。

历史诊断设计及验证记录保存在 `docs/`；当前使用行为以本 README 为准。
