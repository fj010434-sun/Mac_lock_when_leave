# 手表信号诊断

仅在 Mac 安装的原生工具，用于验证指定 Apple Watch 的 RSSI 能否可靠判断离开。**当前为诊断版，不会实际锁屏。Apple Watch 不需要安装应用。**

## 启动

已打包的应用为 `dist/WatchSignal.app`，双击启动。首次点击“开始扫描”时，允许蓝牙访问。应用不自动扫描、不注册开机启动、不读取登录密码。

如果此前拒绝蓝牙访问，在“系统设置 → 隐私与安全性 → 蓝牙”中开启“手表信号诊断”（系统也可能显示 WatchSignal），再暂停并重新开始扫描，必要时重启应用。

## 选定自己的手表

1. 点击“开始扫描”。扫描可能显示手表、手机以及其他蓝牙设备，名称可能为空。
2. 将自己的手表靠近、移远，观察候选设备的信号是否同步变化；不要仅凭名称选择。可结合暂时关闭手表蓝牙/关机观察，单次信号消失不能证明身份。
3. 在左侧选择设备，填写便于识别的名字，点击“确认这是我的手表”。确认后只跟踪该 UUID，其他设备不能替代目标。
4. 如果找不到手表，先导出可获得的数据并记录条件。工具不能保证当前手表型号、系统或熄屏状态一定持续广播。

UUID 是 macOS 为蓝牙设备分配的标识，不是序列号或所有权证明；手表重置、重新配对或地址变化后可能需要重新选择。确认身份需要你操作手表协助观察。

## 校准和判断

- 点击“1 采集工位信号”，在常用坐姿下采集 20 秒。
- 完成后点击“2 采集离开信号”，带着手表走到希望锁屏的位置，尽快站定，等满 20 秒。采样涵盖走开的过程；区分不足时，尝试将 Mac 放到边缘、点击后迅速走开，或重试。
- 每组需至少 10 个有效样本；近、远中位数差值至少 10 dB，否则不会生成有效校准。
- 平滑值持续低于离开阈值 8 秒，记录一次模拟锁屏；返回使用较高的阈值并等待 3 秒。
- 最后样本超过 5 秒显示过期，20 秒无信号可能产生“目标信号丢失”的模拟事件；这不能证明你真的离开。
- 暂停、蓝牙不可用、睡眠和唤醒会清除短期计时；恢复后需要重新收到目标信号并建立在场起点。重新校准和换设备会清除旧校准。

图表保留 120 秒，事件列表保留最近 500 项（界面显示最近 8 项），CSV 保留本次所选设备会话最近 50,000 条采样/事件/校准切换记录；超出容量会显示截断数量。换设备开始新会话。数据仅在本地，主动点击“导出诊断 CSV”才保存文件。

设备名称、UUID 和有效校准保存在 `~/Library/Application Support/WatchSignal/selection.json`。应用重启恢复选择，不会自动确认新设备或恢复旧 EMA。

## 实机验收

这些条件未由自动测试证明，需要戴表参与：

- [ ] 确认确实选中了自己的手表，其他附近同名设备不能替代它。
- [ ] 手表熄屏后观察 10 分钟：记录样本间隔及最长无信号时间。
- [ ] 坐在桌前打字、转腕、转身 10 分钟：记录模拟误锁次数。
- [ ] 在实际锁屏位置做 5 次离开/返回：记录漏判和延迟。
- [ ] 重启应用和手表后仍能识别同一目标，或明确提示需要重新选择。
- [ ] 睡眠/唤醒、蓝牙关闭/开启不会把系统中断当成离开。

诊断通过后，再接入真正的 macOS 锁屏。若信号不持续或身份不稳定，需要评估主动连接/Watch App，而不是单纯放宽阈值。

## 从源码构建

macOS 14+、Swift 6.4（本机环境）、Command Line Tools；无第三方依赖。

```sh
swift run --build-system native DiagnosticsTests
bash scripts/build-app.sh
open dist/WatchSignal.app
```

由于本机 Command Line Tools 不包含 XCTest，测试通过独立 Swift 可执行程序运行：`Core` 或 `Platform` 参数可筛选测试；无参数运行全部。断言失败/筛选不到测试均返回非零退出码。`native` 构建系统在 Swift 6.4 有弃用警告，当前可用。

本地 ad-hoc 签名用于本机运行，不表示 Developer ID 公证或 App Store 发布。重新构建后系统可能需要重新授权蓝牙。

CSV 顶部为导出时的当前校准摘要；每条采样和事件还包含当时的校准版本及阈值。重新校准会记录参数清除/切换边界，历史记录不会被新阈值覆盖解释。
