# WatchSignal 0.2.1 验证记录

用户批准试用“离开判定 → 立即锁屏 → 关闭显示器”，以观察回来唤醒时的 Apple Watch 原生解锁表现。

- `swift run --build-system native DiagnosticsTests`：36 项、0 失败。新增 3 项覆盖同步锁屏与随后熄屏的顺序、无法发出锁屏请求时不熄屏、熄屏失败回调。
- 先对未实现熄屏调度的执行层运行：顺序测试和失败回调测试均失败；实现后全部通过。测试替换 OS 按键发送及显示器休眠操作，没有实际锁屏或熄屏。
- `bash scripts/build-app.sh`：Release 构建、Info.plist 检查、ad-hoc 签名验证均通过。版本 0.2.1 / build 3。
- 独立只读代码审查未发现可操作问题。
- 应用更新并重启；UI 可见“判定离开后立即锁屏，随后关闭显示器”的新版提示，原有校准恢复。
- 新构建在当前设备显示“需要辅助功能权限”，尚需用户重新授权；未由工具修改系统权限。个人 ad-hoc 签名的重建可能使原权限不再识别，不能将系统设置中旧授权视作新版已获得权限。

锁屏按键立即发送，约 0.75 秒后调用固定的 `/usr/bin/pmset displaysleepnow`。命令在后台任务运行，退出状态及失败独立记录为 `displaySleepRequest`；不执行 `sleepnow`，不修改电源管理设置。0.75 秒用于安排顺序，不证明系统已锁屏。

更新前会话已导出到本地 CSV。原始 CSV 不上传仓库。

尚未验证新版真实熄屏和 Apple Watch 自动解锁。用户授权后应先用测试按钮确认锁屏并熄屏，再开启自动锁屏、建立在场起点，离开后返回按键唤醒，观察系统是否自动解锁。
