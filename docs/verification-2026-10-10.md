# 诊断版交付与验证记录

日期：2026-10-10。当前版本不会实际锁屏，Apple Watch 不需要安装应用。

## 已验证

- 独立 Swift 行为测试 26 项全部通过，覆盖目标隔离、校准、EMA、迟滞、新鲜度、信号丢失、暂停/睡眠/权限状态和日志。
- Release 应用构建成功，Info.plist 校验通过，codesign 本地 ad-hoc 签名验证通过。二进制依赖均为系统库，不依赖源码目录。
- 实际启动窗口、初始禁用状态、扫描列表、所选设备实时曲线均已检查。
- 实际扫描发现名为“YIFENG的Apple Watch”的候选设备及其 RSSI；随后界面显示用户选择该设备并完成校准，离开阈值约 -56.8 dBm，返回阈值约 -50.8 dBm。此观察不证明设备的长期身份稳定性或完整误判率。
- 独立代码审查发现两项 P2：重新校准吞掉保存错误、CSV 历史参数归属丢失。新增三个回归场景，先失败后通过，一次修复完成；无遗留审查问题。

## 实施中作出的选择及代价

1. 在附加的隔离工作区开发，源码保留在 feat/watch-rssi-diagnostic 分支；代价是主目录中源码尚未合并，应用可独立使用。
2. CLT 缺少 XCTest，改为独立 Swift 测试程序；代价是未使用 XCTest 工具链。当前 native 构建系统有弃用警告，但测试与构建成功。
3. SDK 27 将裸 @State 解析为 CLT 缺失的宏，采用唯一类型别名 ViewState<Value> = SwiftUI.State<Value> 使用原属性包装器；代价是显式别名，未改动 SDK 或系统设置。
4. 应用启动、睡眠和唤醒通知在 AppDelegate 中管理，调用模型的重置接口；无后台手表 App、无主动连接。
5. 当前只交付本机签名诊断版；Developer ID、公证、上架和实际锁屏留在后续范围，代价是尚不能自动锁屏。
6. 手表熄屏持续广播、重启后 UUID 稳定性以及实际误判/漏判仍需用户参与验证，代价是当前无法承诺长期可靠性。

详细实机清单见 README.md。当前完成的是可运行、可校准、可导出的诊断软件，不代表最终锁屏产品已经验收。
